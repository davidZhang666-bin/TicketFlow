# 架构与一致性

## 当前已实现

React 浏览器 → NestJS API → PostgreSQL 17。API 与独立 Worker 都通过 Redis 7.4、PostgreSQL 进行依赖健康检查。活动发布事务同时写入 Outbox。

领域规则不依赖 NestJS、React 或数据库。HTTP 层使用 Zod 校验；契约生成 OpenAPI 和前端路径类型。运营操作每次重新验证会话与账号角色，查询和命令均绑定活动所有者。

### 活动事务

- 创建：幂等记录加锁 → 活动草稿 → 场次和初始库存 → 保存响应，一次提交。
- 编辑：幂等记录加锁 → 活动行锁 → 校验草稿和版本 → 更新活动、替换场次 → 保存响应。
- 发布：幂等记录加锁 → 活动行锁 → 使用数据库时间校验报名截止 → 更新状态与版本 → 写 Outbox → 保存响应。
- 幂等记录主键为账号、命令作用域、键。请求内容规范化后计算 SHA-256；相同键、不同输入拒绝。
- 库存具有非负约束及 capacity = available + held + confirmed 检查。当前仅初始化库存，尚未开放预约。

Outbox 投递尚未启用，记录保持 PENDING；第3天加入租约、重试、消费去重和死信恢复。

### 认证与运行

会话令牌由32字节安全随机数生成，数据库保存 SHA-256 摘要；有效期8小时。密码使用带独立盐的 scrypt。写请求校验与会话绑定的 CSRF 令牌和提供的 Origin。

服务启动验证依赖。API 和 Worker 均提供 liveness/readiness，收到退出信号时释放连接。应用数据库角色不能创建表；迁移使用独立所有者连接。

## 后续里程碑设计

以下为待实现设计，不代表当前功能。

### 预约与 Redis

PostgreSQL 保持最终约束，Redis Lua 负责高并发准入。预约尝试必须先持久化，再领取有唯一标识的库存令牌。数据库提交或失败补偿均可恢复。

同一活动的 Redis 键使用相同 Cluster hash tag。释放操作依令牌幂等；令牌过期不会直接加回库存。Redis 故障关闭新预约；重建时冻结准入，版本隔离旧请求，按数据库事实恢复。

### 订单、支付与超时

订单资格和支付、退款分别建模。所有路径遵守统一加锁顺序；锁内读取数据库时间，只有截止前仍有效的订单可确认。

订单关闭后的到账、重复的额外交易仍需持久化并退款。支付商调用在事务外，使用商户幂等键、结果查询和响应丢失恢复。

### 消息、候补与取消

事务 Outbox + 至少一次投递 + 消费者幂等。延迟任务和数据库补扫共同推进超时。候补使用数据库顺序，释放事务优先分配给首位有效候补。

活动取消先关闭准入与递补，再按批次处理资格和退款任务。批次可恢复，取消处理完成与所有退款完成分别呈现。

## 当前边界

- 公开列表最多返回最新100个已发布活动；暂不提供分页搜索。
- 当前账号体系为本地演示账号，不含注册、找回密码或外部实名能力。
- 当前登录限流为 API 进程内限流，多实例部署前须调整为共享存储。
